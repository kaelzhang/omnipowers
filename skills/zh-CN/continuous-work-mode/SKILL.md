# 连续工作模式

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
队列靠命令检查，不靠记忆 — 汇报是最后一步，永远不是交付物
```

## 何时使用

- 用户在本会话中开启模式时 → 你 MUST 在下一项工作前启用模式。
- 用户结束模式，或模式对应目标已交付时 → 你 MUST 停用模式。
- 用户未请求模式时 → 你 MUST NOT 启用模式。
- 用户未请求模式时 → 你 MUST NOT 安装闸门。
- 用户未请求模式时 → 你 MUST NOT 询问是否启用。

## 启用模式

闸门不存在时 → 读 `@installing-the-gate.md` 并照做。

- 用户开启模式时 → 你 MUST NOT 询问是否同意安装闸门。
- 用户尚未开启模式时 → 你 MUST NOT 安装闸门。

哨兵文件 — `<project-root>/.omnipowers/continuous-mode`；存在时启用模式，不存在时停用模式，模板如下：

```
goal=<一行：本模式交付什么>
base=<模式开始时的提交>
started=<当前 epoch 秒数>
expires=<模式过期前的小时数>   # 可选，默认 24
defects=<检查清单文件的路径>           # 可选，可重复
repo=<另一个待监控仓库的路径>         # 可选，可重复
```

验收清单 — 位于哨兵文件字段下方，每行一个 `- [ ]` 条目，至少一项；所有条目勾选代表已交付，任一条目未勾选代表未交付。

- 条目写入验收清单时 → 条目 MUST 能在产品中观察到，而非凭记忆确认曾执行的步骤。
- 启用模式时 → 你 MUST 根据用户已陈述的内容一次写完验收清单。
- 启用模式时 → 你 MUST NOT 为产出验收清单开展研究或设计。
- 启用模式时 → 你 MUST NOT 扩大验收清单的范围。
- 验收项落地时 → 你 MUST 将它勾选。
- Git 未忽略 `.omnipowers/` 时 → 你 MUST 在写入哨兵文件前将它加入 `.gitignore`。
- 发出启用确认时 → 你 MUST NOT 以确认消息结束轮次。

## 顺序

检查点（步骤 1）— 任务返回时或轮次结束前，运行 `@checkpoint.sh`，或闸门报告的命令。

派发（步骤 2）— 针对检查点的发现项和未完成验收项，运行 `keeping-work-in-flight` 技能的派发块，包括检查接下来的一段串行工作是否无法拆分。

- 步骤 1 和 2 尚未运行时 → 你 MUST NOT 阅读返回的报告。
- 步骤 1 和 2 尚未运行时 → 你 MUST NOT 撰写回复的任何部分。
- 运行步骤 2 时 → 你 MUST 自己统计仍在运行的工作。

## 结束轮次

合规的轮次结束 — 目标已交付且检查点为空；出现一项 `confirming-with-the-user` 规定由用户决定的事；或用户要求停止。

- 模式已启用时 → 你 MUST NOT 因合规结束条件以外的原因结束轮次。
- 模式已启用时 → 你 MUST NOT 为了问 `confirming-with-the-user` 在“你 MUST NOT 问的事”中列出的问题而结束轮次。
- 模式已启用时 → 你 MUST NOT 以进度总结、任务完成或报告交付结束轮次。
- 正在写“我完成了 X，接下来能做 Y，要我继续吗？”，且 Y 没有阻塞、也不需要裁定时 → 你 MUST 执行 Y，而非发送这句话。
- 无法清除发现项时 → 你 MUST 在报告中点明。
- 无法清除发现项，且闸门放行了本轮时 → 你 MUST NOT 隐去发现项。

## 停用模式

停用 — 删除哨兵文件、相邻的所有者文件、闸门标记、闸门注册项和已安装脚本。

- 模式对应目标已交付时 → 你 MUST 停用模式。
- 用户结束模式时 → 你 MUST 停用模式。
- 工作转为无关任务时 → 你 MUST 停用模式。
- 工作转为无关任务时 → 你 MUST NOT 将启用的模式带入新任务。
- 每个验收项都已勾选时 → 即使检查点仍列有发现项，你 MUST 在同一轮停用模式。
- 检查点存在发现项时 → 你 MUST NOT 将它加入验收清单或为它重新启用模式。
- 停用模式时 → 你 MUST 在自身仍在运行时决定移除。

## 危险信号 — 出现这些想法就停下

| 想法 | 改做什么 |
| --- | --- |
| “这轮做完了，先报告，看看用户怎么说。” | 运行检查点，派发，然后报告。 |
| “写总结时再检查队列。” | 先运行命令。 |
| “问一句是否继续才谨慎。” | 派发没有阻塞的工作。 |
| “闸门放行了，队列肯定清空了。” | 阅读闸门输出。 |
| “用户没在看，先停在这里。” | 只在交付、等待裁定或用户要求停止时结束轮次。 |
| “我来启用模式，会有帮助。” | 只在用户开启时启用。 |
| “闸门在抱怨一个我从未开启的模式。” | 询问用户，然后删除闸门点名的文件。 |
| “目标交付了，先留着模式以防万一。” | 停用模式。 |
| “闸门在停用时没有影响，先保留安装状态。” | 连同哨兵文件一起移除。 |
| “检查点还列着内容，模式就还没结束。” | 将剩余内容作为后续事项报告，并停用模式。 |
| “既然在这个模式里，顺手把这些也修了。” | 将目标设定留给用户。 |
| “要安装 hook 吗？” | 安装，并说明修改了哪个文件。 |
