# 修复 bug

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
复现到红 — 说清根因 — 再修改生产代码
```

- 测试尚未复现 bug，或你尚未亲眼看到测试因 bug 失败 → 你 MUST NOT 修改生产代码。
- 你尚未说清根因 → 你 MUST NOT 提出或应用修复。
- 先写了修复 → 你 MUST 从工作树移除修复，在未修复的代码上用失败测试复现 bug，再放回修复并亲眼看到测试通过。编写测试时，你 MUST NOT 保留修复、暂存修复，或把修复注释后留在原处。
- 你 MUST NOT 编写在有 bug 的代码上通过的测试，并把它称为回归测试。

## 使用时机

- 出现任何技术故障 — bug、崩溃、异常、错误输出、回归、测试失败、性能问题、构建失败、集成问题，或“在我机器上能运行”的反馈 → 你 MUST 应用本技能。
- 问题“看着简单”、只改“一行”，或你赶时间 → 你 MUST NOT 跳过本技能。
- 没有故障，只是在新增能力 → 你 MUST NOT 把本技能扩展到功能开发。

## 复现 — 用失败测试触发 bug

- 你 MUST 产出因 bug 而变红的命令、测试或脚本，并且你 MUST 先亲眼看到红的输出，再继续。
- 复现时 → 你 MUST 在 fixture 中重建触发问题的输入、数据和状态，并断言正确行为 — 报告指定的精确值、错误消息、状态或数量。
- 复现时 → 你 MUST NOT 断言错误行为，或笼统地断言“能运行”。
- 每个复现测试 MUST 覆盖一个缺陷，且测试 MUST 以它锁定的行为命名，读起来像一句话。
- 你 MUST 按宿主项目的测试文件约定，通过宿主项目自己的测试运行器运行测试。

没有明显可用的反馈回路 → 读 `@building-a-feedback-loop.md` 并照做。

- 问题属于**性能**问题 → 反馈回路 MUST 采用带有已记录基线的测量，而非日志。

测试依赖任意时长的延迟 → 读 `@condition-based-waiting.md` 并照做。

- 认真尝试后仍无法构建反馈回路 → 你 MUST 通过 `confirming-with-the-user` 技能向用户求助，记录已尝试的办法，并提出具体请求 — 精确日志、复现步骤、环境信息或访问权限。

### 验证失败 — 确认失败源于 bug

验证测试确实因 bug 失败是 REQUIRED 的。你 MUST NOT 跳过对这次失败的验证。

- 你 MUST 确认测试**失败**而非仅仅运行出错，失败方式**符合 bug 的表现**，且失败由缺陷引起，而非拼写错误或错误导入。
- 复现测试通过 → 你 MUST 修正测试，直到它因 bug 变红。
- 失败方式与 bug 不符 → 你 MUST 继续排查。

## 根因 — 先于任何修复

- 你 MUST 从失败断言追踪到产生错误结果的代码行，并且你 MUST 在根因所在的层次修复，而非症状出现的层次。

失败测试未能直接揭示根因 → 读 `@investigating.md` 并照做。

- 根因未知 → 你 MUST 继续调查。
- 根因未知 → 你 MUST NOT 修补尚未理解的症状，并且你 MUST NOT 假装理解。

## 修复 — 在根因处做最小改动

- 修复时 → 你 MUST 修复根因。
- 修复时 → 你 MUST NOT 修补症状。
- 修复时 → 你 MUST 做最小改动。
- 在同一次改动中 → 你 MUST NOT 重构无关代码、新增功能或修复无关 bug。
- 你 MUST 修复宿主项目真正的生产实现 — 会交付、且复现测试会执行的代码。
- 找不到这份实现 → 你 MUST 继续查找。
- 找不到这份实现 → 你 MUST NOT 用独立的“修正”函数、代码片段或示例代码代替修复。

### 验证通过

验证复现测试通过是 REQUIRED 的。

- 你 MUST 确认复现测试现在**通过**，覆盖改动区域的测试仍然通过，且输出干净 — 没有新增错误或警告。
- 复现测试仍失败 → 你 MUST 修正代码，而非测试。
- 别的测试失败 → 你 MUST 修正代码。
- 验证时 → 对探针标签的 grep MUST 返回空结果，你 MUST 删除临时 harness 和复现脚本，或有意识地将它们转为正式测试，改动说明 MUST 用一行写明已确认的根因。

## 测试陈述要求

- 本应通过的测试失败 → 你 MUST 修正代码。你 MUST NOT 弱化断言、缩小输入范围、删除测试、跳过测试，或标记为预期失败。
- 你认为测试有误，但它未违背用户陈述的任何要求 → 你 MUST NOT 修改测试，直到你引用了你认为它违反的要求，并获得用户明确批准。

## 同类问题排查 — 找出同一根因的所有位置

- 修复已验证 → 你 MUST 搜索代码库中存在相同根因的所有位置 — 相同调用模式、相同缺失检查、相同错误假设、相同复制代码块 — 并且你 MUST 说明运行过哪些搜索。你 MUST NOT 将未运行过的搜索报告为“没有别的位置”。
- 搜到的位置存在缺陷 → 你 MUST 在本次改动中修复，并用没有修复时会失败的测试覆盖。你 MAY 用一个测试覆盖多个位置。修复同类问题排查找到的位置时 → 你 MUST NOT 为每个位置重启整个流程。
- 搜到的位置基于同一假设，但当前不会失败 → 你 MUST 立即消除风险，或记到宿主存放后续工作的地方，并在报告中点名。
- 根因只存在于一个位置 → 你 MUST 明确说明。
- 同类问题排查时 → 你 MUST 只运行根因所限定的搜索，并且你 MUST NOT 审计无关代码。

## 加固 — 覆盖这类缺陷

- 测试集全绿 → 你 SHOULD 为同类缺陷中可能失败的相邻情况（边界、null、零值、并发）添加测试。
- 测试集全绿，且 bug 是无效值进入危险操作 → 你 SHOULD 为这个值经过的每一层添加检查。

测试集全绿，且 bug 是无效值进入危险操作 → 读 `@defense-in-depth.md` 并照做。

- 测试集全绿 → 你 MAY 整理修复代码（命名、重复）。
- 整理时 → 你 MUST 保持所有测试为绿。
- 重构时 → 你 MUST NOT 改变行为。
- bug 已影响用户或生产环境、已经复发，或同类问题排查在两个及以上位置找到它 → 你 MAY 以独立改动跟进低成本加固（校验、断言、lint 规则）。
- bug 已影响用户或生产环境、已经复发，或同类问题排查在两个及以上位置找到它 → 你 MUST NOT 把预防工作混入修复本身。

## 回归测试难写时

测试要做复杂准备、几乎全部 mock，或你无法在一个接缝处隔离 bug → 读 `@hard-to-test.md` 并照做。

## 唯一例外 — 无法复现时

复现测试是 REQUIRED 的。

仅在认真尝试后仍确实无法复现，且在把修复视为完成前满足以下全部三项要求时，你 MAY 跳过复现测试：

1. 你 MUST 完整概述无法复现的原因。
2. 你 MUST 获得用户明确许可，同意在没有复现测试的情况下继续。
3. 你 MUST 在相关生产代码中添加注释，记录没有回归测试及原因。

- 不满足唯一例外 → 你 MUST NOT 跳过复现测试，包括修复看似“显然”“太小”、时间紧急，或附近没有测试的情况。
- 复现困难，或尚未穷尽切实可行的尝试 → 复现测试仍是 REQUIRED 的。
- 复现困难，或尚未穷尽切实可行的尝试 → 你 MUST 继续调查。
- 复现困难，或尚未穷尽切实可行的尝试 → 你 MUST NOT 猜测修复办法。
- 你手动复现了 bug → 复现测试仍是 REQUIRED 的。
- bug 位于第三方代码 → 你 MUST 测试自身对它的使用，锁定所依赖的行为。

## 测试反模式

回归测试要用 mock、stub、fake 或测试专用钩子 → 你 MUST 读 `@testing-anti-patterns.md`，避免测试 mock 行为而非真实行为、向生产类添加测试专用方法，以及在未理解依赖时 mock。

## 危险信号 — 停下

出现以下任一危险信号 → 你 MUST 撤销修复，用失败测试复现，说清根因，再修复：

- “先快速修一下，稍后再查” / “改一下 X 试试” / “大概是 X，我来修”
- “还没完全理解，但这也许能行”
- “只改一行，跳过测试，手动检查就行”
- “我手动复现过了，这就算数”
- “断言太严 / 测试过时了 — 调一下就好”
- “这是修正后的函数” — 用代码片段代替对真实实现的补丁
- “这个 bug 情况特殊……”
- 三次修复失败后说“再试一次”，或每次修复都在别处暴露新问题

三次修复失败后准备再试，或每次修复都在别处暴露新问题 → 读 `@investigating.md` 并照做。

## 验证清单

把 bug 称为已修复前，你 MUST 能勾选每一项：

- [ ] 测试先以符合 bug 表现的方式失败，成功复现 bug
- [ ] 已定位根因；修复根因而非症状
- [ ] 修复改动最小，没有无关改动
- [ ] 复现测试通过；最后一次代码改动后，完整测试集通过一次；输出干净
- [ ] 没有为变绿而弱化、缩小范围、跳过或删除测试
- [ ] 探针已移除，且已验证移除；改动说明写明根因
- [ ] 回归测试保留在测试集中
- [ ] 已排查存在相同根因的其他位置，并写明运行过的搜索
- [ ] 找到的每个位置已在本次改动中修复、消除风险，或记录为后续工作
- [ ] 已覆盖同类缺陷的相邻情况，或说明未覆盖的理由

除满足上述唯一例外条件而缺少复现测试外，仍有任何一项无法勾选 → 你 MUST 重新开始。
