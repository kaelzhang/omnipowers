# 术语表格式 — CONTEXT.md

术语表格式加载条件 — 编写或更新项目术语表（`CONTEXT.md`），或组织多上下文仓库（`CONTEXT-MAP.md`）。

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 结构

```md
# {项目或上下文名称}

{一两句话：这个上下文是什么，为何存在。}

## 语言

**订单**：
客户已确认、已定价且已准备履约的商品请求。
_避免_：购买、交易

**发票**：
交付后向客户发送的付款请求。
_避免_：账单、付款申请

**客户**：
下订单的个人或组织。
_避免_：委托方、买家、账户

## 关系

- 一个**客户**下多个**订单**
- 一个**订单**在交付后产生恰好一张**发票**
```

## 规则

- 编写定义时 → 定义 MUST 用一两句话说明术语*是什么*，而非它做什么、如何实现或在代码中位于何处。
- 多个词语竞争同一概念 → 你 MUST 选择一个规范术语。
- `_避免_` — 列出所有替代前用词的一行。
- 编写术语表时 → 内容 MUST NOT 包含规格、要求、决策历史、实现细节或 TODO。
- 通用编程和基础设施术语（超时、重试、缓存、队列） → 它们 MUST NOT 出现在术语表中，无论项目使用得多频繁。
- 出现自然分组时 → 术语 MAY 按小标题分组。

## 多上下文仓库

限界上下文 — 独立的子领域，同一词语在不同子领域有各自合理的含义。

```md
# 上下文映射

## 上下文

- [订购](./src/ordering/CONTEXT.md) — 接收并跟踪客户订单
- [计费](./src/billing/CONTEXT.md) — 生成发票并处理付款

## 关系

- **订购 → 计费**：订购发出 `OrderPlaced` 事件；计费消费这些事件
- **订购 ↔ 计费**：共享 `CustomerId` 和 `Money` 类型
```

第二个限界上下文出现前 → 你 MUST NOT 引入多上下文结构。
