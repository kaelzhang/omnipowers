# 执行计划

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 计划纪律

- 执行计划时 → 你 MUST NOT 绕开计划临场发挥或跳过验证。

## 流程

### 第 1 步：加载并评审计划

- 采取任何行动前 → 你 MUST 读完计划文件。
- 你在本次会话中编写了计划，并完成了计划所属技能要求的评审 → 你 MUST NOT 重复评审。
- 你未在本次会话中编写计划，或未完成计划所属技能要求的评审 → 你 MUST 批判性评审计划，找出每个问题、缺口、歧义或疑虑。
- 实质性疑虑 — 能改变实现内容、导致步骤失败或使验证失效的疑虑。
- 存在实质性疑虑 → 你 MUST 向用户提出，并在开始执行前解决。
- 实质性疑虑尚未解决 → 你 MUST NOT 开始实现。
- 表面疑虑 — 拼写错误或风格偏好。
- 存在表面疑虑 → 你 MUST 记下。
- 存在表面疑虑 → 你 MUST NOT 为此阻塞执行。
- 实质性疑虑全部解决 → 你 MUST 创建受追踪的步骤检查清单，每步一项；宿主有任务/待办工具时使用工具，否则在回复中维护显式的书面检查清单；随后继续。

### 第 2 步：执行每一步

- 执行计划时 → 你 MUST 严格按计划规定的顺序执行步骤。
- 执行一步时 → 你 MUST 将它标记为进行中。
- 执行一步时 → 你 MUST 严格遵循步骤原文。
- 执行一步时 → 你 MUST NOT 合并、重排或简化步骤。
- 步骤验证 — 步骤指定的验证，按 `verification-before-completion` 判定。
- 步骤指定了验证 → 你 MUST NOT 跳过。
- 执行一步时 → 你 MUST 在验证通过后才将它标记为完成。
- 计划要求在某一步应用特定技术、遵循另一流程或调用特定能力 → 你 MUST 在那一步照做，而非换成自己的方法。

### 第 3 步：完成工作

- 每一步都已完成且每项验证都已通过 → 项目的完整验证（测试、类型检查、linter、构建，以及项目定义的完成闸门）MUST 已在最终工作树上通过；按 `verification-before-completion` 接受在同一工作树上已有的运行，否则运行验证并读取输出。
- 最终验证尚未以实际观察到的输出证明通过 → 你 MUST NOT 声明工作已完成。
- 最终验证通过 → 你 MUST 调用 `finishing-a-development-branch` 技能来集成分支（验证，宿主没有声明 PR 流程时不开 PR、直接合并进目标分支，移除每个已合并的 worktree）。
- 未安装上述技能 → 直接运行宿主项目的分支完成流程：完整测试集为绿、工作树干净，再按项目要求合并或创建 PR。

## 连续执行

- 计划和目标明确 → 你 MUST 以连续工作模式执行：完成所有步骤，中途不停下来征询进度确认。
- 步骤之间 → 你 MUST NOT 问 `confirming-with-the-user` 在“你 MUST NOT 问的事”中列出的任何问题。
- 步骤之间 → 你 MUST NOT 为未经请求的进度总结停下来。
- 步骤之间 → 你 SHOULD 最多用一句短话说明进展。
- 所有步骤完成前 → 你 MUST 仅为“何时停止并求助”列出的阻塞项停止，使用 `confirming-with-the-user` 技能呈现阻塞项（通俗选项 + 你的推荐），取得决定后恢复连续执行。

## 隔离

- 隔离单元 — `using-git-worktrees` 解析并创建的宿主工作单元，包括是否要向任何人确认。
- 编写任何代码前 → 工作 MUST 已位于宿主的隔离单元内。

## 何时停止并求助

- 以下任一情况发生 → 你 MUST 立即停止执行：
  - 遇到阻塞项（缺少依赖、测试失败、环境问题）。
  - 步骤指令不明确，或你不理解。
  - 计划存在关键缺口，导致无法开始或继续。
  - 验证在此前失败后再次失败。
- 停止执行后、呈现阻塞项前 → 你 MUST 让工作脱离本次对话也能恢复：
  1. 提交已完成且完整连贯的工作。
  2. 将阻塞项 — 什么受阻、试过什么、缺什么 — 写入宿主的 work-state 文档；宿主没有此类文档时，写在计划文件中受阻步骤旁。
- 工作已能恢复后 → 你 MUST 使用 `confirming-with-the-user` 技能向用户呈现阻塞项 — 通俗语言、具体选项、你的推荐 — 取得决定后恢复连续执行。
- 执行计划时 → 你 MUST NOT 猜测、编造缺失步骤或强行越过阻塞项。
- 执行计划时 → 你 MUST NOT 悄悄将步骤降级为自己能完成的弱化版本。

## 何时重新检查先前步骤

- 用户根据你的反馈更新计划，或根本方法要重新考虑 → 你 MUST 返回第 1 步（加载并评审）。
- 重新检查第 1 步时 → 你 MUST 评审变更及变更涉及的全部内容。
- 计划发生实质变化，且你尚未评审变更及涉及的内容 → 你 MUST NOT 继续按计划执行。
