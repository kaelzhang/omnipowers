# 解析宿主的提交约定

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

已解析约定 — 项目的暂存方式、提交说明格式和文件追踪策略，在首次提交时解析并约束后续提交，按以下顺序采用首个适用来源：

1. 用户在本次会话中的声明。
2. 宿主 `Omnipowers` 声明中的 `vcs` 行，位置按 `using-omnipowers` 解析。
3. 宿主的贡献指南、提交模板、commit-lint 配置或近期历史中的一致惯例。
4. 本技能的回退约定。

约定的效力 — 仅限形式，能覆盖技能默认值，但不放宽铁律；未提及署名尾注不等于授权添加尾注。

回退标题 — 宿主没有提交说明约定时采用 `type(scope): imperative summary`，使用祈使句，写明改动内容，末尾不加句号。

示意命令 — 本技能展示的 git 命令，受已解析约定约束。

## 危险信号 — 要查阅完整回退约定

| 想法 | 行动 |
|---|---|
| 要查阅完整回退约定——封闭的类型列表、scope 的选择或省略方式、正文要求、破坏性改动标记 | 读 `@message-convention.md` 并照做。 |
