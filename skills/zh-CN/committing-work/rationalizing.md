# 自我开脱 — 驳回

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

| 借口 | 改为这样做 |
|---|---|
| “`git add .` 更快，工作树很干净” | 按路径暂存。 |
| “都是一个功能，一次提交就行” | 拆分能独立评审或撤销的部分。 |
| “后续提交再加测试” | 将测试放入本次提交。 |
| “重命名很简单，顺便带上” | 单独提交重命名。 |
| “`git add -p` 能让提交保持干净” | 按顺序编辑，逐项提交。 |
| “直接 `git commit`——没有暂存别的内容” | 明确列出路径。 |
| “质量标准还没达到，先别提交” | 提交完整一致的检查点，记录缺口。 |
| “先不提交，让用户看看” | 先提交，再向用户指出这次提交。 |
| “看 diff 就懂提交说明” | 写正文说明原因。 |
| “harness 自动添加尾注” | 提交前删除尾注。 |
| “已经推送，但没人拉取” | 用新提交向前修复。 |
| “本次会话早些时候测试通过了” | 现在对即将提交的真实内容运行最小检查。 |
