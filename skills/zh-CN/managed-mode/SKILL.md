# 托管模式

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
靠调研裁定，从不靠询问 — 每项裁定都记录，事后回放
```

## 何时使用

- 用户在本会话中开启模式时 → 你 MUST 在下一项工作前进入模式。
- 用户未请求模式时 → 你 MUST NOT 进入模式。
- 用户未请求模式时 → 你 MUST NOT 询问是否进入。

## 进入模式

托管状态 — `<project-root>/.omnipowers/managed-mode`；存在时模式开启，模板如下：

```
start=<进入时 `date -u +%Y-%m-%dT%H:%MZ` 的输出>
deadline=<start 加上用户说明的时长；用户没说明时加 10 小时>
record=<裁定记录的路径>
```

- 进入模式时 → 你 MUST 写入托管状态。
- 进入模式时 → 你 MUST 为用户陈述的目标启用 `continuous-work-mode`；用户没有陈述目标时，为模式开启时正在进行的工作启用。
- `continuous-work-mode` 的检查点运行时 → 你 MUST 用 `date -u` 的输出对比 `deadline=`。
- 判断是否已到截止时间时 → 你 MUST NOT 凭记忆。

## 裁定

裁定 — `confirming-with-the-user` 规定由用户决定的事。

- 模式开启时 → 你 MUST NOT 请用户作出裁定。
- 模式开启时 → 你 MUST NOT 为等待裁定而结束轮次。
- 出现裁定时 → 你 MUST 按 `researching` 调研业界在同类场景下的做法，结合项目已验证的现状作出决定。
- 宿主提供深度调研能力时 → 你 MAY 用它完成这项调研。
- 作出裁定时 → 你 MUST 把长期架构、架构优雅和成熟的最佳实践排在开发成本之前。
- 作出裁定时 → 开发成本 MUST NOT 决定结果。
- 某个技能要求你确认产物位置时 → 你 MUST 不询问，直接采用那个技能的回退位置。

## 推迟的操作

- 操作属于 `confirming-with-the-user` 列出的难以撤销或对外可见的操作 → 模式开启期间你 MUST NOT 执行，并 MUST 把它记为推迟的操作。
- 推迟的操作挡住了后续工作 → 有可逆路径时，你 MUST 沿可逆路径继续。

## 范围

- 工作在目标之外，包括 `fixing-bugs` 排查找到的目标外位置 → 你 MUST NOT 去做，并 MUST 把它记为建议新目标。

## 裁定记录

裁定记录 — 一个 `design-docs` 产物，位置按 `using-omnipowers` 解析，回退路径为 `docs/design/YYYY-MM-DD-managed-rulings.md`；每项裁定、推迟的操作或建议新目标各占一条：

```markdown
## M<n> — <原本要问用户的问题>
- 类型：裁定 | 推迟的操作 | 建议新目标
- 调研：<一手来源，附引用>
- 选项：<每个选项及其影响>
- 选择：<选项> — 理由：<理由>
- 已做：<提交，或“未做”>
- 回退：<用户否决时如何撤回>
```

- 一项裁定作出后 → 你 MUST 先写下它的条目，再据此行动。
- 实现一项裁定时 → 你 MUST 按宿主的 `vcs` 惯例，把它和其他工作分开提交。

## 退出模式

- 已过截止时间 → 你 MUST 做完并提交手上这一步，不开始新的工作，然后退出。
- 用户结束模式，或 `continuous-work-mode` 因交付而停用 → 你 MUST 退出。
- 退出时 → 你 MUST 停用 `continuous-work-mode` 并删除托管状态。
- 退出时 → 你 MUST 把每条记录作为决策按 `confirming-with-the-user` 呈现给用户，说明已经做了什么、撤回要付出什么代价。
- 用户的答复与记录的选择不同 → 你 MUST 撤回这项裁定的提交，并按答复执行。

## 危险信号 — 出现这些想法就停下

| 想法 | 改做什么 |
| --- | --- |
| “这个选择会定下 schema，归用户决定，我先等着。” | 调研、决定、记录，继续工作。 |
| “用户没有点名免除哪一类确认。” | 本模式免除每一项裁定。 |
| “托管模式不是 continuous-work-mode 的触发词。” | 进入本模式就要启用它。 |
| “截止时间我记得。” | 读 `deadline=`，运行 `date -u`。 |
| “产物位置要先经用户确认。” | 采用回退位置。 |
| “排查规则要求在本次修好另一处。” | 在目标之外，它是建议新目标。 |
| “最后一步自然是删除旧文件。” | 推迟它并记录。 |
