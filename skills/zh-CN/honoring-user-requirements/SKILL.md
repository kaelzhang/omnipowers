# 遵守用户要求

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
行动前先读 — 提出当下就记录 — 作出任何声明前先核验 — 一经确认就原样执行
```

## 台账

长期要求 — 用户提出的、有效期超过一项工作的要求：对每个会话、每项任务或整个项目都有效。

长期台账 — 每个宿主项目一个 `design-docs` 产物，存放这个项目的长期要求，位置按 `using-omnipowers` 解析，回退路径为 `docs/design/standing-requirements.md`。

工作台账 — 每项工作一个 `work-state` 产物，存放这项工作的其他要求，位置按 `using-omnipowers` 解析，回退路径为 `.omnipowers/requirements.md`。

未关闭条目 — 工作台账中尚未勾选的条目。

入口文件要求 — 用户写在宿主加载进你上下文的 agent 入口文件里的要求：用户的全局 `CLAUDE.md` / `AGENTS.md`，或项目的 `CLAUDE.md` / `AGENTS.md`。

长期台账：

```markdown
# 长期要求

- S1 — "<用户原话>"（提出日期 <日期>）
  - 申诉：<你提出的方案> → <用户的答复及时间>
```

工作台账：

```markdown
# 要求

- [ ] R1 — "<用户原话>"（提出日期 <日期>；核验方式：<检查>）
  - 申诉：<你提出的方案> → <用户的答复及时间>
  - 证据：<file:line、命令输出或提交>
- S1 证据：<file:line、命令输出或提交>
```

## 加载

- 会话开始、上下文压缩或中断后恢复，或开始一项新工作时 → 你 MUST 先读长期台账和工作台账的每个未关闭条目，再行动。
- 上下文压缩或中断后恢复时 → 你 MUST 先读每条入口文件要求的原文，再行动。
- 台账条目或入口文件要求与你的记忆或压缩摘要不一致时 → 你 MUST 以台账或入口文件原文为准。
- 为 subagent 或委派运行撰写 brief 时 → 你 MUST 把它的任务可能影响到的每个长期条目和未关闭条目按用户原话写进 brief。

## 记录

- 用户陈述指令、约束、禁令、决策或对申诉的答复 → 你 MUST 在**据此行动前**，用用户原话加入台账。
- 这项要求是长期要求 → 你 MUST 把它加入长期台账。
- 这项要求不是长期要求 → 你 MUST 把它加入工作台账。
- 记录要求时 → 你 MUST NOT 改述成更窄或更宽的要求。
- 记录要求时 → 你 MUST NOT 留到轮次结束再批量录入。
- 宿主自己的入口文件已陈述某项要求 → 你 MUST NOT 复制它。
- 你上下文中的某个技能已陈述某项要求 → 你 MUST NOT 复制它。

## 申诉

申诉 — 对要求有异议或提出更好办法，受 `confirming-with-the-user` 约束。

- 你不认同某项要求，或发现更好的办法 → 你 MUST 在条目下记录申诉和答复。

## 核验

- 结束任何轮次前，以及声称工作已完成、已修复或已就绪前 → 你 MUST 阅读每个长期条目、每个未关闭条目和每条入口文件要求，为每项写一行证据证明已遵守，或标记为**违反**。
- 任务返回时 → 你 MUST 阅读本任务可能影响的每个长期条目、未关闭条目和入口文件要求，为每项写一行证据证明已遵守，或标记为**违反**。
- 为长期条目或入口文件要求写证据时 → 你 MUST 写在工作台账里，不写在长期台账或入口文件里。
- 某条目记录的要求未得到遵守 → 你 MUST 先修正再做任何其他工作，然后重新核验。
- 条目尚无证据 → 你 MUST NOT 声称工作已完成。
- 条目尚无证据 → 你 MUST NOT 在轮次报告中漏报它。
