# 遵守用户要求

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
提出当下就记录 — 作出任何声明前先核验 — 一经确认就原样执行
```

## 台账

台账 — 每项工作对应一个 `work-state` 产物，位置按 `using-omnipowers` 解析，回退路径为 `.omnipowers/requirements.md`。

```markdown
# 要求

## 长期有效
- R1 — "<用户原话>"（提出日期 <日期>）

## 本项工作
- [ ] R2 — "<用户原话>"（提出日期 <日期>；核验方式：<检查>）
  - 申诉：<你提出的方案> → <用户的答复及时间>
  - 证据：<file:line、命令输出或提交>
```

## 记录

- 用户陈述指令、约束、禁令、决策或对申诉的答复 → 你 MUST 在**据此行动前**，用用户原话加入台账。
- 记录要求时 → 你 MUST NOT 改述成更窄或更宽的要求。
- 记录要求时 → 你 MUST NOT 留到轮次结束再批量录入。
- 宿主自己的入口文件已陈述某项要求 → 你 MUST NOT 复制它。

## 申诉

申诉 — 对要求有异议或提出更好办法，受 `confirming-with-the-user` 约束。

- 你不认同某项要求，或发现更好的办法 → 你 MUST 在条目下记录申诉和答复。

## 核验

- 结束任何轮次前，以及声称工作已完成、已修复或已就绪前 → 你 MUST 阅读所有未关闭条目，为每项写一行证据证明已遵守，或标记为**违反**。
- 任务返回时 → 你 MUST 阅读本任务可能影响的所有未关闭条目，为每项写一行证据证明已遵守，或标记为**违反**。
- 某条目记录的要求未得到遵守 → 你 MUST 先修正再做任何其他工作，然后重新核验。
- 条目尚无证据 → 你 MUST NOT 声称工作已完成。
- 条目尚无证据 → 你 MUST NOT 在轮次报告中漏报它。
