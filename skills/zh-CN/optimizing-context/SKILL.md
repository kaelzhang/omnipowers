# 精简上下文

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

## 铁律

```
削减常驻负载 — 保留每条适用规则与裁定原文 — 用测量同时证明两者
```

- 应用本技能时 → 你 MUST 将违反下方任一规则字面要求的行为视作违反规则精神。

## 仅由用户发起与范围

- 用户未明确要求缩减仓库上下文、知识库加载量或模型输入大小时 → 本技能 MUST NOT 触发。
- 你在其他任务中发现常驻指令臃肿时 → 你 MAY 用一句话指出这一情况。
- 用户尚未要求精简上下文时 → 你 MUST NOT 自行重组指令文件。

范围外的相邻工作 — 压缩当前对话会话（归 `writing-handoffs` 或宿主压缩命令）、删减单个技能（归 `writing-skills`）以及日常文档编辑（归 `writing-documentation`）；拆分过程中新建的持久文档组 MUST 遵循 `writing-documentation`，领域术语表或 ADR MUST 遵循 `domain-modeling`。

## 1. 盘点真实加载

运行时加载清单 — 按每个受支持宿主与真实启动目录统计进入模型的全部输入：全局与祖先目录指令、根入口文件、内联 `@` 导入、无路径过滤的规则文件、subagent 预加载技能、自动记忆、激活的 MCP 工具定义、派发简报模板以及高体量命令输出。

- 编辑任何文件前 → 你 MUST 从 agent 实际使用的工作目录和启动模式出发建立运行时加载清单。
- 统计静态字节数时 → 你 MUST 将符号链接解析到唯一权威目标文件只计一次，但在宿主将同一文本重复注入时在运行时加载清单中保留重复项。
- 宿主对祖先与子目录指令实施共享累计字节上限，或在超过行数、字节阈值后截断记忆文件时 → 你 MUST 检查根文件体积是否挤掉或截断了子目录指令。
- 请求针对模型输入大小时 → 你的清单 MUST 纳入闲置的 MCP 服务，以及将原始长输出直接灌入上下文的命令。

## 2. 先剔除再分流

- 代码格式、静态检查或风格规则已由 pre-commit 或 CI 中的确定性工具强制执行时 → 你 MUST 从常驻指令中删除对应的文字重述。
- 静态目录概览只是重复目录树或清单文件中直接可读的路径与职责时 → 你 MUST 将它从常驻指令中移除，只保留反直觉陷阱与准确路由。
- 多处指令来源写有相互冲突的命令或规则时 → 你 MUST 先统一为单一权威来源，再执行拆分。
- 闲置 MCP 服务或高噪原始命令输出推高单轮输入时 → 你 SHOULD 停用闲置服务，并将高噪命令改为精简报告器、过滤脚本或落盘日志，只向模型返回可行动的关键行。

## 3. 确定权威归属

搬迁台账 — 记录每条保留内容的原路径、责任方、加载层级、新路径与核验方式的映射表；拆分跨越多个角色或多组文档时为 `design-docs` 产物（位置按 `using-omnipowers` 解析，回退路径为 `docs/design/YYYY-MM-DD-context-plan.md`），在单轮内仅拆分单一入口时直接作为内联表格写入回复。

加载层级 — 保留内容的五类权威归属：

1. **全员根入口**（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md`） — 首次工具调用前必需的产品边界、即时安全与授权规则、核心构建测试命令及路由。
2. **角色常驻** — 某一 subagent 角色每次受派发都必需、而其他角色不需要的约束。
3. **路径或动作触发** — 带明确路径通配符的宿主路径规则、子目录即时加载文件或按需激活的 `SKILL.md`。
4. **领域或模块契约** — 通过 `writing-documentation` 解析表到达的模块入口与接口契约。
5. **可查询记录** — 通过稳定标识符窄查询、而非整篇通读的裁定库、台账与演进记录。

- 迁移多组文档或调整宿主入口布局前 → 你 MUST 先按 `confirming-with-the-user` 与用户确认搬迁台账，再移动文件。
- 拆分常驻指令时 → 除非某一角色每次运行都需要完整正文，否则你 MUST NOT 用裸 `@path` 导入、缺少路径过滤器的规则文件或 subagent 的 `skills:` 预加载替代原有内联文本。
- agent 从一个检出目录启动去修改兄弟 worktree 时 → 你 MUST 验证路径规则或子目录规则在该启动模式下是否真实触发，并在不触发时补上显式路由。
- 改写派发简报模板时 → 你 MUST 删除重复粘贴的常驻规则块。
- 改写派发简报模板时 → 你 MUST NOT 指示执行者重新读取宿主在启动时已经自动注入的入口文件。
- 记录已批准的通用标准偏离项时 → 你 MUST 在生效处只写一次，点明原规则、批准依据、日期、本地替代规则与维护责任方。
- 历史记录缺少任一偏离项必填字段时 → 你 MUST 向用户指出缺失字段，不编造字段，也不删掉这条偏离记录。
- 拆分裁定库或要求台账时 → 你 MUST 逐字保留每条具约束力的引文、编号、日期与范围，将归档进度日志与现行裁定分离，不把约束性原话缩写成摘要。
- 迁移裁定库或要求台账时 → 你 MUST 对照拆分前的 Git 对象核验守恒性：比对条目多重集，并逐个编号按顺序逐字节比对引文原文。
- 仅引用单个编号却仍被迫读取大块分片时 → 你 SHOULD 提供只返回目标编号内容的窄查询方式。

## 4. 建立闸门并植错验证

- 完成上下文或知识库拆分时 → 你 MUST 提供确定性检查，对加载单元的字节预算、入口可达闭包、链接解析、不重叠的路径属主与生成索引的新鲜度实施拦截。
- 在检查中设定体积预算时 → 你 MUST 按加载器实际读取的单元校验字节数，绝不只校验行数。
- 采信新建或修改后的检查前 → 你 MUST 在一次性副本中分别植入失效链接、超预算文件以及篡改引文或删减记录，确认每类缺陷都使检查以非零状态退出，再确认修复后的目录树通过检查。

## 5. 验证体积缩减与规则存活

- 仓库存在多角色派发、改动影响提示词缓存前缀，或用户要求实测词元节省量时 → 读 `@paired-measurement.md` 并照做。
- 声明优化完成前 → 你 MUST 报告重构前后的权威常驻字节数，并在代表性任务上验证迁出的规则仍能连同来源引用一起被发现，且无关规则包保持未加载状态。
- 评估字节或词元数据时 → 你 MUST NOT 跨不同执行器或模型做对比、脱离总输入与缓存读取量单独报告未命中缓存输入，或将报错、权限受阻、未跑完的轮次算作节省。

## 自我开脱 — 拒绝

| 借口 | 事实 |
| --- | --- |
| “用 `@docs/arch.md` 把 `CLAUDE.md` 缩到了 60 行” | 裸 `@` 导入在启动时全量展开，节省为零；改用反引号包裹路径配任务信号路由，或改用路径规则。 |
| “把 150 条裁定浓缩成 5 KB 摘要更快更干净” | 摘要会抹掉豁免边界与日期；按领域分片并逐字节保留约束性引文。 |
| “让简报写一句 `先读 AGENTS.md` 就不算复制规则” | 宿主启动时已经注入了 `AGENTS.md`；要求重复读取等于双倍消耗上下文。 |
| “检查脚本在当前仓库返回了 0，造假样本测报错太费事” | 空匹配的脚本也会返回 0；先在临时副本中验证每类植入缺陷都会变红报错。 |
| “限制 100 行以内就能防膨胀” | 单行 14 KB 照样绕过行数限制；按加载单元拦截字节数。 |
| “`paths:` 语法合法，在 worktree 里自然也会生效” | 锚定主检出目录的通配符匹配不到兄弟 worktree；按真实启动目录核验触发。 |
| “新运行的首轮输入降了 52%” | 跨执行器对比和权限报错早退制造假节省；同一执行器上完成同等验证才算有效样本。 |

## 危险信号 — 停止

| 想法 | 命令 |
| --- | --- |
| “我用 `@` 导入把大文件拆出去就能省上下文。” | 停下；改用条件路由或带路径过滤的规则。 |
| “我把旧裁定改写成精炼的一句话结论。” | 停下；保留逐字引文并核对字节级守恒。 |
| “编号 D01..D150 在新分片里都在，说明没丢内容。” | 对照 `HEAD` 比对条目多重集与逐编号有序引文。 |
| “检查脚本在重构后的树上跑通了，直接提交。” | 先在临时副本中植入断链、超预算与篡改引文验证脚本必红。 |
