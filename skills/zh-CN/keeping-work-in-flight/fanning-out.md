# 拆分派发工作

> 本文中全大写的规范关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 BCP 14（RFC 2119、RFC 8174）解释，且仅在全大写时具有规范含义。

派发块找到空闲且有排队工作的职责范围时，在派发任何工作前 → 你 MUST 确认以下所有条件：

1. 任意两个任务都不编辑同一个文件、资源、数据库行或配置。
2. 任何任务都不依赖另一个任务的输出、副作用或完成。
3. 仅凭每个任务自身的范围就能完整理解这个任务。
4. 并发 agent 不会在锁、端口、构建产物或生成文件上发生冲突。
5. 每个任务都处于你获授权修改的区域；任务目录已分配给团队、代码负责人或另一个 agent 时 → 通过宿主自身机制转交给负责人。

任一确认失败时 → 你 MUST NOT 并行执行这些任务，且你 MUST 先一并调查这些任务。

## 宿主没有 subagent 时

既没有 subagent，也没有将领域交给负责人的方式时 → 你 MUST NOT 跳过或放弃工作。

## 派发一个 agent

- 派发一个 agent 时 → 派发内容 MUST 包含：它负责的唯一问题、能修改的文件或范围、它 MUST NOT 触碰的内容、要运行的验证，以及要返回的报告。
- agent 与另一个正在工作的 agent 共享文件时 → 你 MUST NOT 派发它。
